# TC-EX01 — Сохранение имени без пробелов по краям

Это образец, составленный помощником, а не выполненный учеником тест.

**Требования:** R-01, R-06.
**Сборка:** qa-rc.1.
**Статус:** Не выполнен.

## Предусловия
Стенд http://127.0.0.1:8770 доступен. В Postman подготовлен запрос, Authorization — No Auth.

## Тестовые данные
Content-Type: application/json.
Перед ivan и после него — по одному обычному пробелу.

```json
{
  "name": " ivan ",
  "amount": 50000,
  "consent": true
}
```

## Шаги и ожидаемые результаты

| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Отправить POST http://127.0.0.1:8770/api/applications с указанным JSON | 201. В ответе name="ivan", amount=50000, consent=true, status="new". Получен положительный целочисленный id |
| 2 | Сохранить полученный id; отправить GET http://127.0.0.1:8770/api/applications/{полученный id}, тело запроса пустое | 200. id совпадает с выданным на шаге 1; name="ivan", amount=50000, consent=true |

## Постусловие
Создана одна учебная заявка. Её id нужно записать при фактическом выполнении. Удаление в этом API не предусмотрено.

## Фактическое выполнение
Не выполнялся в рамках этого примера.
Фактический id, ответы, дата и доказательства: не предоставлены.

## Почему так
POST показывает результат создания, GET проверяет сохранённое представление через API чтения. Конкретный id заранее не задаётся: он появляется при выполнении.
В этом кейсе проверяем удаление крайних пробелов; внутренние пробелы и другие варианты имени требуют отдельных проверок.
