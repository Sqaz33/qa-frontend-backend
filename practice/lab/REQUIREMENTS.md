# Требования: учебные заявки

Учебный вымышленный продукт, не система реальной компании. Сборка для приёмочного тестирования: **qa-rc.1**.
Стенд: http://127.0.0.1:8770. Данные полностью отделены от прежних демо.

## Правила
| ID | Требование |
|---|---|
| R-01 | Имя обязательно, строка; после удаления пробелов по краям от 2 до 50 символов включительно. Сохраняется без крайних пробелов. Внутренние пробелы не удаляются |
| R-02 | Сумма обязательна, целое число рублей от 1000 до 100000 включительно |
| R-03 | API не принимает строку, null, boolean, дробное число или отсутствие поля вместо суммы; даже числовая строка не подходит |
| R-04 | Без согласия заявка не создаётся. API принимает consent только как JSON true |
| R-05 | И интерфейс, и API проверяют ограничения независимо. Ошибка API не должна показываться как успех |
| R-06 | Успешная заявка получает положительный целочисленный id, status=new и created_at; имя, сумма и согласие сохраняются согласно правилам без иных преобразований |
| R-07 | Результат отправки и список в интерфейсе показывают точную сумму в рублях; разделители разрядов допустимы, округление суммы недопустимо |
| R-08 | После обновления страницы заявка остаётся в списке; API списка и чтения по id согласованы |
| R-09 | При ошибке валидации API даёт ошибку поля и не создаёт/не изменяет заявки |
| R-10 | При сетевой ошибке UI показывает, что результат не удалось подтвердить; ложный успех недопустим. До повторного POST следует проверить, создалась ли заявка |
| R-11 | Во время отправки кнопка заблокирована; после завершения отправки или ошибки её можно использовать снова |
| R-12 | На странице видна версия сборки. Она совпадает с /health и X-Build-Version ответов API |

## Границы задания
Входа, ролей, удаления, редактирования, фильтрации и расчёта процентов здесь нет.
Каждый успешно обработанный POST создаёт новую заявку. Идемпотентность и защита от повторного POST не обещаны.
Повторное чтение GET не создаёт заявки. Дополнительные JSON-поля игнорируются.
Список возвращает все записи, новые первыми; данные локальные и учебные, пагинации нет.
Фиксированный перечень состояний: только new.
Время created_at — UTC ISO 8601, точное значение заранее неизвестно.
Данные сохраняются в SQLite между перезапусками сервера.

## Начальное состояние
Новая база при первом запуске пуста. Тестовые данные помощника хранятся отдельно и не являются вашими результатами.
Если вы уже запускали стенд, ориентируйтесь на свой исходный список и id, не ожидайте определённых номеров.

## Рабочий процесс
Сначала прочитайте требования и API-контракт. Подготовьте 8–12 строк чек-листа и два подробных тест-кейса.
После этого проведите smoke и проверки выбранных рисков. Не заглядывайте в преподавательские материалы/реализацию до собственного исследования.
Если нашли отклонение: сохраните факты, повторите, обоснуйте локализацию и заполните баг-репорт.
Исправленную сборку получите после разбора отчёта; затем ретест, регрессия и заключение по выпуску.

Сборка предоставляется для тестирования: её соответствие этим требованиям ещё должен оценить ученик.
