# API-контракт итоговой практики

База: http://127.0.0.1:8770. Авторизация не используется.
Этот документ задаёт ожидаемое поведение; наблюдаемое отклонение от него может быть дефектом сборки.
Основные правила R-01–R-12: [требования](REQUIREMENTS.md).

## Общие свойства
JSON UTF-8; заголовки JSON-ответов: Content-Type: application/json; charset=utf-8, Cache-Control: no-store, X-Build-Version, X-Request-Id (непустой уникальный id ответа).
Не сравнивайте случайные id запросов и время с жёстко записанными примерами.

## GET /health
200:
```json
{"status":"ok","build":"qa-rc.1"}
```
build отражает текущую установленную сборку; после исправления может измениться.

## POST /api/applications
Content-Type: application/json (параметр charset=utf-8 допустим).
Тело — объект JSON:
```json
{"name":"Тестовый пользователь","amount":50000,"consent":true}
```

Все три поля обязательны. name — строка, amount — JSON integer, consent — boolean true.
Число с дробной частью и запись вроде 1000.0 не соответствуют правилу JSON integer этого упражнения.
При успехе: 201 и Location: /api/applications/{id}.
Ответ:
```json
{
  "id": 1,
  "name": "Тестовый пользователь",
  "amount": 50000,
  "consent": true,
  "status": "new",
  "created_at": "2026-10-24T09:00:00+00:00"
}
```
id и время в примере условные. Вернётся фактически созданная запись, доступная через GET по id и в списке.

### Ошибки
| Условие | Статус и error | Изменение данных |
|---|---|---|
| Нарушены правила name/amount/consent | 422 validation_error; fields содержит сообщения для каждого недопустимого поля | Нет |
| Сломанный JSON/не UTF-8 | 400 invalid_json | Нет |
| Тело — не объект, пустое или более 65536 байт | 400 invalid_body | Нет |
| Некорректный Content-Length | 400 invalid_length | Нет |
| Другой/отсутствующий Content-Type | 415 unsupported_media_type | Нет |

Если неверны несколько уровней, сначала проверяется Content-Type, затем длина и синтаксис, затем поля.
Пример ответа для недопустимой суммы:
```json
{"error":"validation_error","fields":{"amount":"Сумма: целое число от 1 000 до 100 000 рублей"}}
```
Точный текст сообщений не проверяется посимвольно: важны код, нужное поле, непустое понятное описание и отсутствие ложного успеха.
Дополнительные поля в запросе игнорируются.

## GET /api/applications
200:
```json
{"items":[]}
```
items — массив записей той же структуры, что в успешном POST. Новые записи первыми.
Уже созданные заявки не меняются от GET или неуспешного POST.

## GET /api/applications/{id}
Существующая запись → 200 и объект заявки.
Неизвестный/некорректный id → 404:
```json
{"error":"not_found","message":"Заявка не найдена"}
```

## Остальные запросы
Неизвестный путь → 404 not_found.
PUT/PATCH/DELETE и другие методы, кроме GET/POST/HEAD, → 405 method_not_allowed с Allow: GET, POST, HEAD.
HEAD для существующих ресурсов возвращает заголовки соответствующего GET без тела, не меняет данные.
Query-параметры не входят в упражнения: GET их игнорирует, фильтрация не поддерживается.

## Сопоставление с браузером
Форма отправляет POST на тот же API. Для локализации сравните введённые данные, Payload, Response и показанное значение; при необходимости повторите запрос в Postman и прочитайте созданную запись.
