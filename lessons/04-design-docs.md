# 4. Тест-дизайн и документация

## Эквивалентные классы
Разделить значения на группы с ожидаемо похожей обработкой. Например, для целой суммы 1000–100000: ниже минимума, допустимый диапазон, выше максимума. Пустое значение и неверный тип — отдельные проверки.

## Границы
Для включительного целочисленного диапазона 1000–100000 проверить 999, 1000, 1001, 99999, 100000, 100001. Перед выбором данных уточнить включительность границ, допустимость дробей и правила формата.

## Таблица решений
Использовать, когда результат зависит от сочетания условий. Например: обязательные поля заполнены / согласие дано. Перечислить допустимые комбинации и ожидаемую возможность отправки.

## Переходы состояний
Проверять разрешённые и запрещённые переходы, если заявка проходит состояния. Не выдумывать состояния без требований.

## Документы
- Чек-лист: краткие проверки и результаты.
- Тест-кейс: воспроизводимый сценарий с условиями, шагами и ожиданиями.
- Баг-репорт: конкретное несоответствие с доказательствами.
- Отчёт: объём проверки, результаты, дефекты, риски и ограничения.

Использовать templates/. Не подставлять вымышленные фактические результаты.

## Задания
Составить 12–15 проверок формы заявки, 2 подробных тест-кейса и один баг-репорт по реально наблюдавшемуся дефекту. Обосновать выбор данных и приоритет проверок.
