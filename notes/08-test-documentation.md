# Чек-лист, тест-кейс и баг-репорт

**На повторение: 4 минуты.** Примеры оформлены помощником на основе выполненных учеником проверок.

## Для чего нужен каждый документ

| Документ | Что в нём записываем | Пример |
|---|---|---|
| Чек-лист | Краткие проверки, ожидания и результаты | Проверить сумму 999: ошибка, новой записи нет |
| Тест-кейс | Условия, данные, точные действия и ожидания | Создать заявку на 1000, сохранить id, прочитать её и сравнить поля |
| Баг-репорт | Конкретное несоответствие ожиданию | Писать после реально обнаруженного отклонения |

Чек-лист тоже может содержать ожидаемый результат и тестовые данные. Разница обычно в детализации, а не в жёстком запрете на определённые поля.
Формат зависит от команды и сложности сценария.

## Один сценарий в двух форматах

В чек-листе:
«Создать заявку на 1000 и получить по id — данные совпадают».

В тест-кейсе:
1. Задать исходные условия и JSON.
2. Отправить POST по конкретному адресу.
3. Проверить ожидаемые поля и статус.
4. Сохранить полученный id.
5. Отправить GET с этим id.
6. Сравнить данные.

Тест-кейс должен позволять другому человеку повторить проверку без дополнительных догадок.

## Ожидаемое и фактическое

| Ожидаемое | Фактическое |
|---|---|
| API выдаёт id созданной заявки | В текущем выполнении получен id=4 |
| GET возвращает те же данные | Пользователь сообщил: «все совпало» |
| Для суммы 999 сервер отклоняет запрос | На скриншоте 422 и ошибка fields.amount |

Ожидание берём из требований и контракта. Факт — из выполненной проверки.
Не записывать код ответа или поле как наблюдавшиеся, если они только были в инструкции.

## Повторное использование
В шагах пишем «полученный id», а id=4 сохраняем в записи конкретного выполнения.
При повторе номер может измениться.

## Когда оформлять баг
Нужно показать различие ожидаемого и фактического результата.
В проверенных сценариях отклонения не обнаружены. Ошибка валидации 422 для 999 соответствует требованиям.
Баг-репорт по этим результатам не нужен.

- evidence/TC-001-boundary-1000.md — тест-кейс и отдельная запись выполнения.
