# POST → GET: создать заявку и проверить сохранение

**На повторение: 3 минуты.** Инструкция к следующей проверке; результат ученика пока не получен.

## Что уже проверено
Сумма 999 отклоняется сервером: на скриншоте видны 422 и fields.amount.
После инструкции сравнить список до и после пользователь сообщил: «не появилось записи».
Отсутствие новой записи подтверждено сообщением пользователя; отдельного скриншота сравнения списков нет.

## Почему теперь 1000
По требованию допустимы целые суммы от 1000 до 100000 включительно.
999 находится сразу за нижней границей, 1000 — сама допустимая граница.
На 1000 ожидается успешное создание.

## Шаг 1. Создать
В POST http://127.0.0.1:8765/api/applications оставить raw JSON:
```json
{
  "name": "test",
  "amount": 1000,
  "consent": true
}
```

Content-Type: application/json.
Отправить один раз. Ожидается 201.
В ответе проверить amount=1000, name=test, consent=true, status=new; записать выданный id.
Каждый успешный POST в этом стенде создаёт отдельную заявку.

## Шаг 2. Прочитать
Создать GET http://127.0.0.1:8765/api/applications/{id}.
Вместо {id} подставить id из только что полученного ответа. Тело GET — none.

Ожидается 200. В ответе должны совпасть id, name, amount, consent, status и created_at с ответом создания.
Фиксировать фактический ответ, а не подставлять ожидаемые значения.

## Что устанавливает проверка
POST показывает результат операции создания. Последующий GET подтверждает, что созданные данные доступны по API под тем же id.
Это не прямое исследование базы данных и не проверка поведения после перезапуска сервера.

| Проверка | Ожидаемый результат |
|---|---|
| POST с 999 | 422, новая запись не добавлена |
| POST с 1000 | 201, заявка создана |
| GET по полученному id | 200, данные совпадают с созданными |

## Формулировка для интервью
> Проверил значение ниже границы и саму границу. Для 999 сервер вернул ошибку, новая запись не появилась. Для допустимой суммы проверяю создание и затем читаю ресурс по полученному id, чтобы сравнить сохранённые данные.

Последняя фраза описывает текущий план; результат POST/GET с 1000 ещё не подтверждён учеником.
