# Smoke, ретест и регрессия

**На повторение: 3 минуты.** Вводная заметка; тема ещё не проверена на практике.

## Три разных вопроса

| Проверка | На какой вопрос отвечает | Пример |
|---|---|---|
| **Smoke** | Основные функции сборки работают, можно продолжать проверку? | Вход, открытие профиля, выход |
| **Ретест** | Конкретный дефект исправили? | Повторяем шаги из баг-репорта на новой сборке |
| **Регрессия** | Изменение не повредило связанные функции? | После правки входа проверяем другие способы входа и отказы |

Объём smoke зависит от продукта. Регрессию выбирают по изменению и рискам; она может затрагивать и удалённые части системы через общие зависимости.

## Один случай из практики

**Было:** пользователь сбросил пароль, но войти с новым паролем не мог. Разработчик выдал исправленную сборку.

**Ретест:**
1. Повторить исходные условия из баг-репорта.
2. Сбросить пароль.
3. Войти с новым паролем и сравнить результат с ожидаемым.

**Регрессия рядом с исправлением:**

| Что проверить | Зачем |
|---|---|
| Старый пароль больше не подходит | Сброс не должен оставлять старый доступ |
| Вход другого пользователя работает | Правка могла затронуть общий механизм входа |
| Неверный пароль отклоняется | Исправление не должно разрешить ошибочный вход |
| Повторный сброс пароля работает | Изменение могло затронуть весь сценарий сброса |

Ожидаемое поведение сверяем с требованиями приложения.

## Как объяснить на собеседовании

> Сначала повторю сценарий из баг-репорта на исправленной сборке — это ретест. Затем проверю связанные функции, которые могла затронуть правка, — это регрессия. Её объём выберу по изменениям и рискам.

## Частые ошибки

- Повторить только исходный баг и назвать это регрессией.
- Начать проверку, не убедившись, что установлена нужная сборка.
- Выбирать проверки без объяснения, как они связаны с изменением.

## Проверь себя

1. На новой сборке перестал открываться профиль. Что это значит для дальнейших проверок?
2. После исправления сброса пароля ты повторил исходный баг. Как называется эта проверка?
3. Зачем проверять вход другого пользователя?
