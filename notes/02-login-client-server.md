# Как работает вход на сайт

**На повторение: 3 минуты.** Первый ответ и краткий ответ о cookie разобраны; практика ещё впереди.

## Цепочка

| Шаг | Что происходит |
|---|---|
| 1. Действие | Пользователь вводит данные и нажимает «Войти» |
| 2. Запрос | Браузер отправляет данные серверу по HTTPS; приложение может сначала проверить заполнение полей |
| 3. Проверка | Сервер находит пользователя и проверяет введённый пароль по сохранённому хешу |
| 4. Ответ | Сервер сообщает результат; при успехе создаёт сессию или выдаёт токены по правилам приложения |
| 5. Интерфейс | Браузерный код обрабатывает ответ: открывает нужный экран или показывает ошибку |

Пароль из хеша не расшифровывают. Для проверки используют функцию проверки пароля выбранного алгоритма с данными сохранённого хеша.

## Токены и cookie — разные вопросы

**Access/refresh** описывает назначение токенов. **Cookie или доступное JavaScript хранилище** описывает способ хранения и передачи. Эти варианты могут сочетаться.

Приложение может использовать:
- access-токен и refresh-токен;
- один токен;
- серверную сессию с идентификатором в cookie.

Конкретную схему узнаём из документации и запросов приложения. Содержимое cookie не обязательно JWT или access-токен.

## Что означает HttpOnly

Сервер передаёт cookie заголовком ответа `Set-Cookie`. Браузер сохраняет её, если правила браузера это позволяют.

Атрибут `HttpOnly` запрещает JavaScript читать эту cookie через `document.cookie`. Такая cookie при этом доступна для исследования в DevTools.

Браузер может сам прикладывать cookie к следующим запросам. Отправка зависит от адреса, атрибутов cookie и условий запроса.

## Что было верно в твоём ответе

Ты назвал отправку запроса, проверку хеша пароля, несколько вариантов выдачи данных для входа и ответ сервера. Это подтверждает понимание основной цепочки.

Уточнение: назначение токенов и доступность из JavaScript — разные признаки. Также вместо токена сервер может использовать обычный идентификатор сессии.

2. Как сервер узнаёт пользователя в следующем запросе, если cookie имеет HttpOnly?

Основная идея второго вопроса разобрана: cookie к запросу прикладывает браузер. Подробные условия отправки ещё не проверяли.
