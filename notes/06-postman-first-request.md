# Postman: первый прямой запрос

**На повторение: 4 минуты.** Инструкция подготовлена для Postman 12.33.1. Прямой POST выполнен учеником; 422 подтверждён скриншотом.

## Зачем это делать
Форма отклоняет сумму 999 до отправки. Через Postman отправим данные прямо в API и проверим, что ограничение существует на сервере.

## Начало
Открыть настольный Postman. Для отправки первых запросов можно использовать lightweight API Client без входа в аккаунт.
В этом режиме доступны запросы и история. Для организации в коллекции и работы с environments нужен workspace.

Источник: [официальная документация lightweight API Client](https://learning.postman.com/latest-v-12/docs/getting-started/basics/using-api-client).

## Запрос
Создать HTTP-запрос (New → HTTP).
Метод: POST.
URL: http://127.0.0.1:8765/api/applications

В Body выбрать raw и формат JSON:
```json
{
  "name": "Тестовый пользователь",
  "amount": 999,
  "consent": true
}
```

Проверить, что заголовок Content-Type имеет значение application/json, затем нажать Send.

| Часть | Зачем нужна |
|---|---|
| POST | Операция создания заявки по контракту этого API |
| URL | Адрес учебного сервера и путь ресурса |
| Body | Данные запроса |
| Content-Type | Сообщает серверу формат тела |
| Send | Отправляет запрос независимо от формы сайта |

## Ожидаемый ответ по контракту
HTTP-статус 422. Тело:
```json
{
  "error": "validation_error",
  "fields": {
    "amount": "Сумма: целое число от 1 000 до 100 000 рублей"
  }
}
```

422 с этой ошибкой — ожидаемое отклонение недопустимых данных.
Один код 422 не подтверждает, что ошибка именно в сумме: нужно проверить fields.amount.

## Проверить, что заявка не создалась
До негативного запроса выполнить GET /api/applications и сохранить список.
После него выполнить тот же GET. При отсутствии других отправок новая запись появиться не должна.
Если отрицательный запрос уже выполнен без исходного списка, повторить сценарий с фиксацией состояния до и после.

## Если ответ другой

| Результат | Что проверить сначала |
|---|---|
| Не удаётся подключиться | Запущен ли demo/server.py, адрес и порт 8765 |
| 404 | Путь /api/applications |
| 415 | Content-Type: application/json |
| 400 | Корректность JSON, кавычки и запятые |
| 422 с другими полями | name и consent в теле |

## Что фактически выполнено
Пользователь увидел в браузере ограничение суммы >=1000 при вводе 999.
Отсутствие нового POST пользователь отдельно не сообщил.
На скриншоте пользователя: POST с name=test, amount=999, consent=true → 422, error=validation_error и fields.amount. Проверка отклонения суммы пройдена. После инструкции GET → POST → GET пользователь сообщил, что новая запись не появилась. Отдельные снимки сравнения не предоставлены.

## Подсказка Fix в Postman
Если AI предлагает исправить amount, это не означает, что тест провалился. В этом запросе 999 задано намеренно; ожидаемый результат — отклонение. Для позитивного сценария будет отдельный запрос с допустимой суммой.
