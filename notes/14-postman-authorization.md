Практика подготовлена на отдельном auth-demo-1.0, порт 8766: [вход, токен и роли](23-postman-auth-hands-on.md). Открытый demo-1.0 на 8765 остаётся без авторизации.

**На повторение: 3 минуты.** Здесь объяснение; защищённых endpoints в demo-1.0 нет.

## Authorization не выдаёт права
Эта вкладка настраивает, как клиент отправит данные для проверки сервером.
Выбор Bearer Token без подходящего действующего токена не авторизует пользователя.

| Режим | Что передаёт |
|---|---|
| No Auth | Не добавляет аутентификацию этого типа |
| Bearer Token | Authorization: Bearer <token> |
| Basic Auth | Логин и пароль в Base64-представлении; Base64 не шифрует данные |
| API Key | Ключ в заголовке или query согласно контракту |
| OAuth 2.0 | Настройка получения и использования токена по соответствующей схеме |

Использовать защищённое соединение для реальных учётных данных. Не копировать действующие секреты в учебный репозиторий или чат.

## Наследование
Общие настройки можно задать на уровне коллекции, а запросу выбрать Inherit auth from parent.
Не дублировать Authorization вручную в Headers без причины: сначала выяснить, какой заголовок действительно ушёл.

В нашей коллекции установлен No Auth: локальный демонстрационный API открыт.
Добавлять выдуманный токен для успешного запроса к нему не требуется.

## Что проверять на защищённом API
По контракту: запрос без данных аутентификации, неверный/истёкший токен, подходящий токен и необходимые права.
401 обычно означает отсутствие подходящей аутентификации; 403 — запрет доступа. Реальный API может скрывать наличие ресурса через 404 — ожидания задаёт контракт.
Получение 200 на нашем открытом API не доказывает работоспособность Bearer-аутентификации.

## Хранение секретов
Адрес стенда можно хранить в environment. Действующие токены — в подходящем хранилище секретов, например Vault, или временно в локальном контексте.
Маскировка значения в интерфейсе сама по себе не гарантирует, что экспортированный файл не содержит секрет.
Перед передачей коллекции/окружения проверить содержимое файлов.
