# Что такое стенд и как начать практику Postman

**На повторение: 3 минуты.**

## Стенд
Стенд — подготовленная среда, где запущено приложение определённой версии с нужными настройками, данными и зависимостями.
В web-сервисе это могут быть frontend, backend, база, внешние интеграции или их учебные замены.

| Среда | Типичное назначение |
|---|---|
| Local | Запуск на компьютере разработчика или тестировщика |
| Test / QA | Проверка изменений командой |
| Stage / Preprod | Проверка в условиях, приближённых к production |
| Production | Рабочая система с реальными пользователями |

Названия и устройство сред зависят от команды. Stage не гарантирует полного совпадения с production.

## Наш стенд
Версия demo-1.0: форма, Python API и SQLite на этом компьютере.
Базовый адрес: http://127.0.0.1:8765.

- 127.0.0.1 — этот компьютер.
- 8765 — порт учебного сервера.
- /health — путь проверки доступности.

Postman — клиент стенда, а не сам стенд.

## Стенд и Environment
Стенд — реально запущенное приложение и окружение его выполнения.
Environment в Postman — набор переменных, с которыми клиент обращается к стенду.
Создание QA Local в Postman не запускает Python-сервер и не создаёт базу данных.

## Практика вручную
Пользователь хочет сам настроить весь блок в Postman. Готовая коллекция остаётся образцом для сверки; импорт не является обязательным первым действием.

1. Через + в боковой панели создать Collection с именем QA — практика.
2. Создать или открыть Environment QA Local.
3. Добавить включённую переменную baseUrl=http://127.0.0.1:8765.
4. Выбрать QA Local в верхнем переключателе окружений.
5. В своей коллекции создать запрос «01 — Доступность стенда».
6. Метод GET, адрес {{baseUrl}}/health, Body none, Authorization No Auth.
7. Сохранить запрос и отправить.

Ожидание: 200 и JSON с status=ok, build=demo-1.0.
На присланном скриншоте: сохранённый GET {{baseUrl}}/health, активное QA Local, 200 OK, status=ok и build=demo-1.0. Первый ручной шаг выполнен.

## Что будет дальше
Сами создадим POST, проверки pm.test, переменную id, зависимый GET, набор негативных данных и прогон Runner.
Для реальных упражнений на 401/403 потребуется отдельный защищённый учебный endpoint. Текущий demo-1.0 открыт; не представлять запросы к нему как проверку авторизации.
