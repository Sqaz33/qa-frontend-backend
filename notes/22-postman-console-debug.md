# Postman Console: как понять, что пошло не так

## Открыть и увидеть запрос
1. Нажми Console внизу Postman или Ctrl+Alt+C в Windows.
2. Открой «01 — Доступность стенда», GET {{baseUrl}}/health. Выбери QA Local и нажми Send.
3. Раскрой запись GET в Console. Посмотри фактический URL, заголовки запроса, код и тело ответа.

В запросе используется переменная, а в сетевой записи должен быть разрешённый адрес http://127.0.0.1:8765/health. Если адрес другой, проверь выбранное окружение и переменные с тем же именем в других областях.

Test Results показывает результат твоих утверждений. Console помогает исследовать запрос, ответ и ошибки выполнения. Она не показывает внутреннюю работу сервера и не заменяет серверные логи.

## Разные виды проблем

| Наблюдение | Что это значит | Что проверить сначала |
|---|---|---|
| Could not send request / ECONNREFUSED | Соединение отклонено, HTTP-ответ от этого API не получен | Правильный ли хост и порт, запущен ли сервер |
| SyntaxError в скрипте | Ошибка JavaScript | Номер строки, скобки, кавычки; в Before request или After response ошибка |
| AssertionError | Фактическое значение не совпало с ожиданием | Сообщение проверки, запрос, ответ, затем требование |
| 422 и PASSED | Сервер отклонил данные так, как требовалось негативным сценарием | Правильная ли причина отказа и нет ли побочных эффектов |

SyntaxError из pm.response.json() может означать, что ответ не содержит корректный JSON, а не ошибку скобок в самом скрипте. Читай место и текст исключения.

## Порядок расследования
1. Тот ли стенд, адрес, метод и путь?
2. Что реально отправлено: заголовки, тело, число или строка?
3. Какой фактический ответ: статус, тип содержимого, данные?
4. Что обещает контракт?
5. Правильны ли ожидание и код проверки?
6. Нужны ли GET для проверки состояния, серверные логи и X-Request-Id?

FAILED — сигнал исследовать расхождение. Возможны дефект API, ошибка теста, неправильные данные или настройки. Один статус не определяет front/back.

## Учебный пример
Если POST получил 201, amount в ответе равен числу 1000, а тест ждёт 999, исправлять нужно ожидание в тесте — при условии, что запрос и требования действительно задают 1000. Если отправили 1000, а API вернул 999, сохраняй фактические запрос/ответ и проверяй состояние через GET.

## Особенность запроса 04
Теперь его Before request читает строку из файла Runner. Обычный Send вне прогона не предоставляет iteration data. Сообщение «Подключи файл данных в Runner» в этой ситуации — предусмотренная защита учебного скрипта, не дефект сервера. Для простого просмотра Console используй GET /health.

Не выводи пароли и токены в console.log и проверяй содержимое перед передачей логов другим людям.
