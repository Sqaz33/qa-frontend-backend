# DevTools: от формы до ответа сервера

**На повторение: 4 минуты.** Первый позитивный сценарий выполнен пользователем на demo-1.0.

## Что открывать

Chrome → F12 → Network → Fetch/XHR.
Открывать журнал до действия. Нажать «Создать заявку», затем выбрать запрос applications.

| Вкладка | Что смотреть |
|---|---|
| Headers | Request URL, Request Method, Status Code; заголовки запроса и ответа |
| Payload | Тело запроса: какие значения действительно ушли |
| Response | Тело ответа: какие значения вернул сервер |

Fetch/XHR — удобный фильтр API-запросов этого примера. Отсутствие записи под фильтром само по себе не доказывает, что никакого запроса не было: при исследовании также проверяют фильтры и запись журнала.

## Реальный результат первого сценария

Источник — сообщение пользователя от 21 октября 2026.

| Этап | Наблюдение |
|---|---|
| Форма | Сумма 50 000 |
| Запрос | Сумма 50 000 |
| Ответ | Сумма 50 000 |
| Интерфейс после отправки | Сумма 50 000 |
| HTTP-статус | 201 |

По предоставленному результату проверка согласованности суммы прошла.
201 Created означает, что сервер сообщил о создании ресурса. Код проверяют вместе с содержимым ответа и фактическим результатом операции.

В этом сценарии пользователь не сообщил id заявки, время запроса или снимки экрана. Их не следует придумывать.
Один позитивный сценарий не покрывает граничные значения, ошибки, права доступа и остальные функции.

## Клиентская валидация — следующий шаг

Остальные поля оставить корректными. Очистить журнал Network, ввести сумму 999 и нажать «Создать заявку».

В этом стенде у поля есть HTML-ограничение min=1000. Ожидаемое поведение:
- браузер показывает сообщение о недопустимом значении;
- обработчик отправки не выполняется;
- новый POST /api/applications не появляется.

Это ожидаемая клиентская проверка. Отсутствие запроса здесь не является дефектом.

## Серверная валидация

Клиентская проверка срабатывает в браузере. Серверная — на backend при получении запроса.

Если форма заблокировала 999, это ещё не подтверждает серверную проверку. Для неё отправим JSON с amount=999 напрямую из Postman.

Контракт demo-1.0: ожидается 422 с ошибкой поля amount, новая заявка не создаётся.
Это ожидание следующего пользовательского сценария; пользователь его пока не выполнил.
Помощник отдельно проверял отклонение 999 при подготовке стенда.

## Что пригодится в баг-репорте

Адрес и версия стенда, шаги, тестовые данные, метод и URL запроса, статус, очищенные тело запроса и ответ. При наличии — id ресурса и X-Request-Id.

## Фраза для интервью

> Нашёл запрос в Network, сравнил значение в форме, отправленном теле, ответе и интерфейсе. Все четыре значения совпали, сервер вернул ожидаемый 201. Затем отдельно проверю недопустимые данные и серверную валидацию.
