# Практика Postman вручную

Пользователь сам создаёт запросы, окружения и скрипты в приложении. Помощник объясняет действия и разбирает результаты.
Готовая коллекция — образец. CLI-проверки помощника не считаются выполнением ученика.

## Маршрут и фактический статус

| Шаг | Тема | Статус |
|---|---|---|
| 1 | Коллекция, QA Local, baseUrl, GET /health | Подтверждено скриншотом: 200 и demo-1.0 |
| 2 | POST на 1000 и три проверки ответа | Скриншот: 201, 3 PASSED; показана коррекция функции третьего теста |
| 3 | Намеренно неверное ожидание | FAILED подтверждён сообщением |
| 4 | Передача id из POST в GET | Пользователь сообщил «сделал»; отдельные id и статусы не предоставлены |
| 5 | Неверный тип amount | Скриншот: 422 и fields.amount; все проверки прошли по сообщению ученика |
| 6 | Некорректный JSON и Content-Type | 400: пользователь сообщил «все»; выполнение 415 не подтверждено |
| 7 | Before request и строка данных | Формирование JSON с сохранением типов |
| 8 | Runner и наборы данных | Цепочка и прогон с данными выполнены по сообщениям; счётчики отдельно не предоставлены |
| 9 | Console, области переменных | Разрешённый адрес и ошибки скриптов |
| 10 | Авторизация | auth-demo-1.0 на 8766 подготовлен и проверен помощником; ручная практика впереди |

## Блок завершён для текущего прохода
По просьбе пользователя возвращаемся к основному плану. Успешный вход и проверки ролей не подтверждены: последний скриншот показал GET /auth/login вместо POST, коррекция объяснена. Не требовать завершения auth перед темами дефектов и релизов. Подробный маршрут для повторения — [заметка 23](../notes/23-postman-auth-hands-on.md).

Не требовать теоретического опроса после каждого шага и не ставить PASSED без наблюдения или сообщения пользователя.
Для авторизации использовать отдельный auth-demo-1.0 с контрактом auth-demo/README.md. Открытый demo-1.0 не подтверждает auth.
Итоговый кейс с неизвестным дефектом сохранить отдельным от демонстрационных примеров.
