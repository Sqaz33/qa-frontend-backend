# Практика Postman вручную

По просьбе пользователя все учебные операции он выполняет сам в Postman. Помощник объясняет действия и разбирает результаты.
Готовые файлы — эталон для сверки. CLI используется помощником для проверки заготовок и по желанию ученика позже; он не подменяет практику в приложении.

## Последовательность

| Шаг | Что ученик настраивает | Что проверяем |
|---|---|---|
| 1 | Коллекция QA — практика, QA Local, baseUrl, GET /health | Подстановка адреса, сохранение запроса, 200 и сборка |
| 2 | POST с JSON и Content-Type | Создание, типы полей, 201 |
| 3 | Scripts → Post-response с pm.test | Статус и содержимое ответа, причины failed |
| 4 | Сохранение id в collection variable и GET с подстановкой | Цепочка создания/чтения без ручного номера |
| 5 | Негативные суммы, неверный JSON и Content-Type | Различия 422, 400 и 415 по контракту |
| 6 | Pre-request и переменные из строки данных | Формирование корректного JSON с разными типами |
| 7 | Runner, JSON-набор, результаты | Порядок запросов, итерации, отсутствие побочных эффектов |
| 8 | Console и отладка | Разрешённые переменные, фактический адрес, ошибки скриптов |
| 9 | Авторизация на отдельном защищённом учебном примере | Передача токена и проверки доступа по контракту |

Сейчас выполнять только шаг 1. Объяснять следующий шаг после текущего, без обязательного теоретического опроса.
Не отмечать действия выполненными по одному наличию готового файла.
Авторизацию не имитировать на открытом demo-1.0: перед шагом 9 подготовить отдельный демонстрационный endpoint с явным контрактом и учебными учётными данными/ролями. Не раскрывать при этом дефекты финального кейса.

## Текущий запрос
GET {{baseUrl}}/health; Body none; Authorization No Auth.
Ожидание: 200, status=ok, build=demo-1.0.
